# 综测记录架构说明

本文面向维护者，解释 `v0.1.x` 的模块边界、持久化约束和主要故障处理方式。它描述的是 Windows 单机版，不涵盖多用户、云同步、移动端或数据加密。

## 系统边界

```text
React / Fluent UI
        |
        | 类型化 Tauri IPC
        v
Rust 模块化单体
  |-- 记录与类别
  |-- 附件与存储
  |-- 统计
  |-- Excel、材料包与备份
  `-- Tauri Updater
        |
        +-- SQLite
        +-- 内容寻址附件库
        +-- 恢复点
        `-- GitHub Releases（仅更新时访问）
```

界面不能直接读写数据库或任意文件。所有业务写入、路径校验、哈希计算和恢复操作都由 Rust 命令执行。GitHub 不参与日常数据操作，断网只影响更新检查。

## 核心约束

- 记录 ID、类别 ID 和附件 ID 使用 UUID；重复提交同一个 ID 不应创建额外对象。
- 日期在 IPC 和 SQLite 中均为本地 `YYYY-MM-DD`。
- 分数在 IPC 中为最多两位小数的字符串，在 SQLite 中保存为整数百分位。统计只累计整数，不使用浮点数。
- 学年从 9 月 1 日开始，到次年 8 月 31 日结束。
- 记录更新使用 `revision` 做乐观并发控制。版本不一致时返回 `REVISION_CONFLICT`，不覆盖较新的数据。
- 删除是软删除，记录保留 30 天。恢复和永久删除都可以按 ID 重试。
- 单条记录最多 20 份附件，每份不超过 200 MB。

## 持久化布局

默认数据根目录由操作系统应用数据目录决定，逻辑布局如下：

```text
数据根目录/
|-- 综测记录.sqlite3
|-- materials/
|   `-- <sha256 前缀>/<sha256>
|-- recovery/
|   `-- <日期时间>/
`-- staging/
```

SQLite 初始化时启用外键、WAL 和忙等待，并在迁移后执行完整性检查。数据库是记录、类别和附件引用关系的事实来源。附件文件按 SHA-256 内容寻址，同一内容只保留一份；原文件名、MIME 类型和大小保存在数据库中。

保存记录时先校验全部输入，再复制并校验新附件，最后提交数据库事务。事务失败可能留下未引用的内容文件，但不会留下半条记录；后续附件回收会清理未被当前记录、回收站或恢复点引用的文件。

## 模块职责

| 模块           | 主要职责                                    | 不负责                   |
| -------------- | ------------------------------------------- | ------------------------ |
| 记录与类别     | CRUD、筛选、分页、乐观锁、软删除、30 天清理 | 直接操作附件内容         |
| 附件与存储     | 大小/数量校验、哈希去重、归档、打开与回收   | 解析业务分数             |
| 统计           | 共享筛选、整数分数聚合、学年与月度分组      | 缓存独立统计副本         |
| Excel 与材料包 | 模板、预览、幂等导入、明细/汇总、ZIP 清单   | 静默覆盖既有附件         |
| 备份与恢复     | SQLite 快照、引用附件、清单校验、合并或替换 | 把内部恢复点当作异盘备份 |
| 更新器         | 检查 GitHub Release、签名校验、用户确认安装 | 强制更新或上传业务数据   |

## IPC 约定

命令按 `records`、`categories`、`materials`、`statistics`、`excel`、`backup`、`storage` 和 `updater` 的业务边界组织。JSON 字段使用 `camelCase`。写命令返回更新后的对象或统一的操作结果。

错误使用结构化对象：

```json
{
  "code": "REVISION_CONFLICT",
  "message": "记录已在其他窗口中更新，请重新打开后再保存",
  "details": {}
}
```

界面根据 `code` 决定是否提示重试、重新加载、选择其他目录或进入恢复界面，不依赖中文消息做控制流判断。

## 导入、导出与备份

Excel 导入分为预览和提交两步。预览阶段识别表头别名、逐行校验、标记新增/更新/跳过/疑似重复；提交阶段重新验证预览令牌并在单个事务中写入。同一令牌重复提交不会重复导入。

材料包是 ZIP，包含记录明细 Excel、`manifest.json` 和按记录划分的材料目录。写入前会清理 Windows 非法文件名并处理重名；读取 ZIP 或备份时拒绝绝对路径、父目录穿越和超出限制的解压内容。

`.zcbak` 完整备份包含格式清单、SQLite 一致性快照和所有仍被引用的附件。合并恢复保留本地数据；替换恢复先在暂存目录验证，再切换数据目录并保留可回滚副本。内部恢复点仅用于近期误操作，默认保留最近 7 个。

## 存储迁移

迁移前计算数据库、附件和恢复点的总大小，并检查目标可用空间。复制结束后逐项校验大小或哈希，只有全部通过才更新数据根目录指针。旧副本在成功切换后处理。若自定义数据盘不可用，应用进入恢复状态，不能静默创建空数据库。

## 更新与信任边界

应用最多每 24 小时后台检查一次 GitHub Releases，手动检查不受此限制。`latest.json` 只提供版本和下载元数据；安装前仍必须通过编译进应用的 Tauri 公钥验证更新签名。

首版安装器没有商业 Authenticode 证书，因此 Windows 可能显示“未知发布者”。这不降低应用内更新签名的要求。私钥只保存在 GitHub Actions Secrets 和仓库外的加密恢复副本中，不能提交到 Git。

## 主要故障模式

| 故障             | 行为                                         |
| ---------------- | -------------------------------------------- |
| SQLite 写入失败  | 回滚事务并返回结构化错误，不更新界面本地状态 |
| 附件复制中断     | 不提交记录；未引用文件可在后续回收           |
| 自定义数据盘失联 | 进入恢复界面，不创建新库                     |
| Excel 或备份损坏 | 预览/校验失败，不修改现有数据                |
| 磁盘空间不足     | 在复制或导出前拒绝操作，并指出目标目录       |
| GitHub 不可达    | 保留当前版本，日常记录功能继续工作           |
| 更新签名无效     | 拒绝安装，保留当前版本和数据                 |
